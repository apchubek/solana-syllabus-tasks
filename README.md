# Rust Solana Coursework Repository

This repository contains a sequence of assignments for the course "IT Startup Final Project 1 (DS/ML Startup)" with a focus on Solana, Rust, Anchor, Web3, and practical dApp development.

## Repository structure

- `assignment-1/` - first transaction on Solana
- `assignment-2/` - transaction detective and Solana transaction analysis
- `assignment-3/` - Rust CLI and mock runtime / account serialization
- `assignment-4/` - first standalone Solana program and Devnet deployment
- `assignment-5/` - Anchor counter program and client integration
- `assignment-6/` - PDA-based on-chain profile and client integration

## Documentation layout

Each assignment folder contains two documentation files:

- `README.md` - project overview, structure, and usage notes
- `task.md` - the original assignment goal and acceptance direction

Some subfolders also include their own README files when they contain a separate deploy or client workflow.

## How to navigate the repo

Start with the assignment folder that matches the week or topic you want to review, then open the local README for implementation details.

Typical progression:

1. Read the assignment `task.md` to understand the original requirement.
2. Read the assignment `README.md` to see the current implementation and structure.
3. Open the code in `src/`, `programs/`, `client/`, or `deploy/` as needed.

## Assignment mapping to the syllabus

- Week 1 - first transaction and Solana Explorer workflow
- Week 2 - real transaction analysis and transaction structure
- Week 3 - Rust fundamentals for Solana development
- Week 4 - first Solana program
- Week 5 - Anchor framework and counter program
- Week 6 - accounts, PDAs, and on-chain profile architecture
- Week 7 - SPL tokens and token extensions

The later assignments continue the same course direction: building, testing, deploying, and documenting Web3 applications on Solana.

## Documentation status

The repository is organized so that every assignment can be reviewed independently while still fitting into one long-form portfolio. If you extend the project, keep the local README and task file updated with the scope of the change.
